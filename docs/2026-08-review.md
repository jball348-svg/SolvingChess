# Repository review, August 2026

A full audit of the repository as it stood before this session, and a record of
what was kept, changed and removed.

## What was there

Fifteen files: three research notes, six directory-stub READMEs, three Python
files implementing one experiment, and two agent-instruction files.

The prose was directionally sound. The engineering was not.

## Findings

### 1. The one recorded experimental result was wrong

`experiments/symmetry_compression/results.md` recorded:

```
Raw states: 78
Reduced states: 13
Compression: 83.33%
```

Running the committed code produces:

```
Raw states: 156
Symmetry classes: 21
Compression: 86.54%
```

The numbers had been written down rather than pasted from a run, and never
checked. This is the finding that mattered most, because everything downstream of
a recorded result inherits its trustworthiness. Fixed by making every experiment
write a machine-readable `results/*.json` alongside its markdown, so the two
cannot drift.

### 2. The experiment counted positions, not states

`generate_positions` enumerated `(white_king, black_king)` pairs and ignored side
to move, so it was counting half a state space. The 156 placements correspond to
312 states.

### 3. The symmetry group was assumed, not derived

`D4` was hard-coded. That is correct for two bare kings on a square board and
wrong almost everywhere else: a pawn kills the rank mirror and both diagonals
(group order drops from 8 to 2), a rectangular board kills the diagonals, and
symmetric material *adds* a colour swap that the original code did not have.
Applying `D4` to a universe containing a pawn produces a compression figure for
a transformation that does not preserve the game.

Fixed in `src/solvingchess/symmetry.py`, which derives the group per universe --
and, more importantly, provides `verify()` to re-check it against a solved table
rather than trusting the derivation.

### 4. The module could not be imported

`find_equivalence_classes.py` did `from enumerate_positions import ...`, which
only works when the interpreter is launched from inside that directory. There
was no package, no `requirements.txt`, no test suite, and no way to run anything
from the repository root.

### 5. The README described a structure that did not exist

It documented `engine/`, `simulations/` and `visualisations/`. None existed.
Meanwhile `geometry/`, `mathematics/` and `notebooks/` existed and held nothing
but a README each.

### 6. The research notes overlapped heavily

`wrong_mathematical_space_hypothesis.md` and
`4d_chess_mathematical_foundations.md` restated the same 4D lattice material,
the same rook displacement example and the same quotient-space idea. Roughly 60%
duplication.

### 7. The central hypothesis was not falsifiable

"Chess may be difficult because it is represented in the wrong mathematical
space" had no accompanying definition of "better representation", no measurement,
and no outcome that would count against it.

### 8. The source paper was not identified

The README linked a bare MDPI URL. It is Kaufmann, "A Mathematical Framework for
Four-Dimensional Chess", *AppliedMath* 6(3), 48, 2026
([doi:10.3390/appliedmath6030048](https://doi.org/10.3390/appliedmath6030048)).
Notably, that paper makes no claim that four dimensions simplify chess -- a claim
the repository's notes were edging towards attributing to it.

### 9. No prior art

Nothing referenced Gardner's 5x5 minichess (weakly solved, a draw, 2013), the
checkers proof (2007), or Watkins' solution of Losing Chess (2016). All three are
directly relevant: the first is *the same idea already executed at a larger size
than we can reach*.

## Kept

* The core intuition that representation and symmetry are worth measuring. It
  was right, and it is now measured.
* The 4D lattice framework as a source of clean graph-theoretic objects --
  rewritten with the citation and an honest cost-benefit assessment.
* The `research/` directory as the corpus, and `notebooks/`.
* `AGENTS.md`'s stance against "replace mathematical investigation with larger
  computation". That is a good rule and it survives verbatim in spirit.

## Removed

* `geometry/`, `mathematics/` -- empty stubs. Their content belongs in the
  corpus and the kernel, and both now have it.
* `experiments/representation_space/` -- a roadmap masquerading as an
  experiment. Folded into `docs/roadmap.md`.
* The three original scripts, superseded by the kernel.

## Added

* **A micro-chess kernel** (`src/solvingchess/`): arbitrary rectangular boards,
  full legal move generation including promotion, check, checkmate and
  stalemate; exact backward induction for loopy games; symmetry groups derived
  per universe; bisimulation quotients.
* **Known-answer tests.** The solver reproduces the published maximum
  distance-to-mate for KQ vs K (10 moves) and KR vs K (16 moves) on 8x8. Every
  structural claim in this repository rests on that.
* **The minification programme** (`research/05`): Singleton Chess, the ladder,
  and the first solved rungs.
* **Note 07**, which argues against the programme's central assumption. A
  research repository that only contains arguments for its own hypothesis is not
  doing research.
* Prior art, glossary, ranked mechanism list, roadmap, `Makefile`,
  `requirements.txt`, `.gitignore`.

## Honest assessment of the repository's premise

The founding hypothesis is that chess is hard partly because of how we represent
it. The first real measurement of that hypothesis -- experiment 001 -- came out
*against* the strong form: symmetry compression achieves its group-order ceiling
and no more, and the ceiling is 16.

That is not a reason to stop. It is a reason to move the question to where it is
still open, which is experiment 003's structure gap: whether there is redundancy
that geometry cannot see. The repository now states its own negative results
prominently, which is the main structural change beyond the code.
